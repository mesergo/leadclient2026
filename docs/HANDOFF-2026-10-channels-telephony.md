## 2. החלטות מוצר/עיצוב

### 2.1 הסתרת שם הספק מהלקוח
**אסור** ששם ספק הטלפוניה יופיע באף מחרוזת תצוגה ללקוח (כולל `agency_admin`).

- כל טקסט תצוגה עם שם הספק הוחלף ב-"טלפוניה" / "ספק הטלפוניה" / "טלפוניה (ברירת מחדל)".
- **ערכי enum, שמות עמודות, שמות שדות ב-API, והערות קוד — לא שונו** (לא נחשפים ללקוח).
- דרופדאון הספק (VirtualPage / AgencyEdit) מציג את ערך הספק הראשי כ-"טלפוניה (ברירת מחדל)"; ה-`value` נשאר.
- לוג ה-Webhook: מקור השיחה מוצג כ-"שיחה" במקום שם פנימי.

**כלל המשך:** כל פיצ'ר/טקסט חדש — לבדוק שאין שם ספק גלוי. יש כבר regex שמסנן URLי ספק מתוך raw data (`client/src/tags.js`).

### 2.2 ערוץ = מספר אחד
לפי החלטת מוצר, ערוץ מחזיק מספר וירטואלי יחיד. בלוק "הוסף מספר" הוסר מה-UI. (ראוט השרת והקונטקסט נשארו — משמשים ביצירת ערוץ חדש.)

### 2.3 "הגדרות נוספות" מקופל
כל ההגדרות המתקדמות של הערוץ מאחורי כפתור toggle. ברירות מחדל:
- **אחוז הקלטה** — מוסתר, **תמיד 100%**.
- **הכרזת הקלטה למי** — דיפולט **לעונה** (`record_option=2`).
- **הצגת מזהה מתקשר** — דיפולט **המספר הווירטואלי** (`expose=1`).
- **greeting_in / greeting_out / ringback** — **מוסתרים** עד שייבנה מנגנון ההקלטות. העמודות נשמרות ב-DB, והערכים לא נמחקים בשמירה (PATCH מעדכן רק שדות שנשלחו).

> שים לב: יש שתי תוויות toggle שונות בעמוד — "**אפשרויות ניתוב**" (סוג הפניה + משך צלצול, רמת מספר) ו"**הגדרות נוספות**" (הקלטה + מזהה מתקשר, רמת ערוץ). לא לבלבל.

## 3. אינטגרציית ספק הטלפוניה (REST)

מקור אמת לתיעוד: **https://help.maskyoo.com/developers/api/rest-api/maskyoo**
(ה-Swagger הישן ב-portal מיושן/לא זמין — לא לסמוך עליו.)

### 3.1 ערכי פרמטרים (אומת 2026-10)
| פרמטר | ערכים |
|-------|-------|
| `dial_option` | **1**=מקביל (סימולטני, דיפולט), **2**=טורי (hunt), **3**=IVR (call router). טווח 1–3. |
| `record_option` | 1=למתקשר, 2=לעונה, 3=לשניהם. (מי שומע את הכרזת ההקלטה; ההקלטה עצמה נשלטת ע"י `record_percentage`.) |
| `record_percentage` | 0–100 (0=ללא הקלטה). alias: `record_presantge`. |
| `expose` | 1=המספר הווירטואלי (דיפולט), 2=המתקשר, 3=אנונימי. |
| `callback_url_option` | 1=תחילת שיחה, 2=סוף (דיפולט), 3=שניהם. אנחנו משתמשים ב-3. |
| `working_hours` | bitmap שבועי של **168 תווים** בדיוק. מחרוזת קצרה יותר נדחית בשקט (לא נשמרת, בלי שגיאה). |

### 3.2 כללים חשובים
- `update_maskyoo` **מחייב** `call_destination_phone` בכל קריאה — גם כששומרים שדה אחר (אחרת שגיאה 4012). לכן אנחנו קוראים `get_maskyoo` קודם, מעתיקים את כל השדות, ומחליפים רק מה שצריך — כך update (שמחליף רשומה שלמה) לא מוחק כלום.
- `create_time` לא נשלח חזרה ב-update.
- **IVR**: הניתוב בתפריט מוגדר **אצל הספק**. אנחנו שולחים `dial_option=3` + `call_destination_phone` כ-fallback; לא בונים את התפריט דרך ה-API.

### 3.3 קוד רלוונטי
- `server/src/services/maskyoo.js` — `syncRouting(number, routing, extra)`, `createCall()`, `syncTags()`, `getRecording()`.
- `server/src/routes/services.js` — `syncMaskyoo(phoneNumberId)` בונה `routing` + `extra` מרשומת הערוץ וקורא ל-`syncRouting`.
- `client/src/pages/EditServicePage.jsx` — טופס עריכת ערוץ.
- `client/src/components/RedirectConfig.jsx` — רכיב ניתוב (סוג הפניה כולל IVR + מספרים + צלצול).

> תיעוד פנימי נוסף (ערכי API) נשמר ב-memory של הסשן: `reference_maskyoo_api.md`.

## 4. בדיקות שבוצעו
- PATCH/GET round-trip — כל 6 שדות ההגדרות + 168 תווים + טלפון אחרי-שעות נשמרו.
- 14 בדיקות מיפוי `extra`→payload (record/expose/greetings/working_hours/after-hours) — PASS.
- Edge: ערך מחוץ לטווח מדולג, ערך קיים בספק נשמר, `create_time` לא נשלח — PASS.
- מיפוי dial_option: parallel→1, sequential→2, ivr→3 — PASS.
- כל `vite build` עבר.

בדיקות ה-unit הן סקריפטים חד-פעמיים (stub ל-`fetch`), לא בחבילת טסטים קבועה. **פער ידוע:** אין עדיין test suite אוטומטי.
